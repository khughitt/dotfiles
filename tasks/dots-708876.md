Found on titan 2026-09-08 while fixing dots-e4570d. niri/noctalia.kdl, hypr/noctalia.conf, hypr/noctalia/noctalia-colors.conf, kitty/themes/noctalia.conf, zathura/noctaliarc and opencode/themes/noctalia.json are regular files inside the Dropbox-shared dotfiles tree: gitignored, so git is silent, but synced, so each machine's Noctalia overwrites the other's. They are generated from per-machine prism values that genuinely differ (titan carries glass.jellyFlex/jellyRipple/paneLip; europa carries a different ior, roughness and compositor.gaps). Noctalia's builtin templates write through ~/.config/<app>, which symlinks into the tree. This is the content form of dots-e4570d; the dotfiles-health check added there only inspects symlinks and does not catch it. Verified: synced, gitignored, in-tree, inputs differ. Not yet observed: the overwrite itself, since europa was not running. Candidate fixes: route the outputs through XDG_STATE_HOME as host.kdl now is, or extend dropbox_ignore_flux, which already owns com.dropbox.ignored but only for churn directories. Outcome: generated per-machine output no longer lands in the shared tree, and dotfiles-health catches generated files there, not just symlinks.

## Notes

- 2026-09-08T22:32:05Z (main): Noctalia's four generated theme outputs (niri/noctalia.kdl, hypr/noctalia.conf, kitty/themes/noctalia.conf, zathura/noctaliarc) are now symlinks into XDG_STATE_HOME, so per-machine colours no longer sync. Spike established Noctalia writes through a symlink rather than replacing it: a sentinel in each state file was rewritten with real theme content in 2s while every link survived. The list lives in lib/dotfiles-setup-data.bash; setup.sh makes the links (migrating any existing regular file) and dotfiles-health fails if one is a real file or resolves back into the tree. Root cause: exactly the four config dirs that are whole-directory symlinks into the tree leak; the six real ~/.config dirs do not. Also removed a dead v4 leftover, hypr/noctalia/noctalia-colors.conf.
