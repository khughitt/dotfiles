Build output syncs through Dropbox: dropbox_ignore_flux (shell/functions.d/dropbox.zsh) covers node_modules, .venv and caches, but not dist, build or .svelte-kit. In mindful v6 on 2026-09-24, packages/web/build (403 MB) and packages/web/.svelte-kit (399 MB) churned on every web build, and packages/mindful/dist on every npm test/typecheck; those three were marked by hand that day.

Add dist, build and .svelte-kit to the flux's default names, guarded because the names are generic (as work-link guards target with Cargo.toml): mark a candidate only when its owning repository reports it ignored (git check-ignore) and git ls-files lists nothing tracked under it. A candidate outside any repository, or one that fails the guard, is reported and skipped, not marked. Extend tests/dropbox_ignore_flux.zsh with a tracked dist (skipped), an ignored dist (marked), and a build dir outside git (skipped).

Not work-link: package.json main/exports/bin point into dist, and Node resolves a symlinked dist to its real path, so imports from it would miss the repo's node_modules.

Tools that wipe and recreate the directory (SvelteKit clears .svelte-kit and build) drop the attribute until the next flux run, up to 2h. Mitigation lives in each project's build script (mind6 filed separately); update the setup_cmd comment in ops templates/justfile to name build output alongside node_modules.
