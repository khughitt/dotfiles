# lookout v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a read-only terminal overview of live agents, task state and obs failure signals,
shown in a niri kitty quick-access dropdown, that is instant to open and never shows a
guessed number.

**Architecture:** independent data sources, each on its own refresh schedule, publish
`SourceState<T>` (last good data, age, unavailable reason) into pure model functions. The
model functions build an immutable `View`, and an OpenTUI (Solid) layer renders it. Every
source reads only a tool's own command or published file, through an injectable `Exec`
and an injectable clock, so the tests run on fixtures.

**Tech Stack:** TypeScript, Bun 1.4, `@opentui/core` and `@opentui/solid` 0.5.11 (as
mindful-tui pins), `solid-js` ^1.9, `bun test`, Biome. kitty graphics protocol for the
portraits.

**Spec:** `docs/specs/2026-10-18-ops-dashboard-design.md`. It lives in dotfiles until
Task 1 copies it into lookout.

## Global Constraints

- Read-only. No `tasks` write, no lock taken, no `tasks/*.md` parsed, no attempt
  directory or thought or inbox body read.
- Never read the obs index from a refresh loop, and never run `obs index`,
  `dashboard build` or `ANALYZE`. Read only
  `$XDG_STATE_HOME/obs/dashboard/snapshot.js`.
- Refresh schedules:
  - agents: on changes to familiar's directory, plus a claims read every 2 s, plus a timer
    at each intent `expiresAt`
  - tasks: every 30 s
  - obs: on changes to the snapshot file
- A failing source keeps its last good data with its age, or shows
  `unavailable (<reason>)`. It never shows a guessed zero.
- `personal` projects only, chosen by `ops-profile resolve <root> --json`. One host per
  view, named in the header.
- Doing splits into claimed (with unverified kept visible), parked and unattended, over
  the one reconciled population (spec, Constraints).
- Task 1 creates the project as `lookout`: tasks prefix `look`, checkout `~/d/lookout`,
  `personal` profile, GitHub `khughitt/lookout`.
- Gated actions, which the owner approves in the moment:
  - creating the GitHub repository and pushing to it
  - `just projects` in ops plus `just assemble` in lore (a live global-instructions change)
  - any use of the live desktop (the spike, the live checks)

## Review Focus

1. **A source that is down at start-up** (no snapshot on europa, no familiar directory):
   that module reads `unavailable (<reason>)` and the others render normally. Pinned in
   Task 3 and Task 8.
2. **A worktree that a claim or park names has been removed:** the task falls back to its
   registered record and the dashboard does not throw. Pinned in Task 5.
3. **Clock and day boundaries:** obs days are cut in the snapshot's own `tz`
   (America/Los_Angeles) while the host runs US/Eastern. "Yesterday" is obs's yesterday.
   Pinned in Task 6.
4. **A session whose pid is gone but whose familiar record is still current:** it is not
   counted as live. A claim reported `live: true` with `unverified` shows as unverified.
   Pinned in Task 4 and Task 5.
5. **A burst of familiar file renames** (atomic replace: several events per write):
   one recompute per burst, with no partial reads. Pinned in Task 4.

### Task 3: Sources: last good data, age, and unavailable reasons

**Files:**
- Create: `src/source.ts`, `src/clock.ts`, `src/exec.ts`
- Test: `tests/source.test.ts`

**Interfaces:**
- Produces:
  - `interface Clock { now(): number; setTimeout(fn: () => void, ms: number): () => void }`
  - `systemClock: Clock`, and a `fakeClock(start: number)` that has `advance(ms)`
  - `type Exec = (cmd: string[], opts?: { cwd?: string; timeoutMs?: number }) => Promise<{ code: number; stdout: string; stderr: string }>`
  - `bunExec: Exec`
  - `interface SourceState<T> { data: T | null; at: number | null; error: string | null; reading: boolean }`
  - `class Source<T>`:
    - `constructor(opts: { name: string; read: () => Promise<T>; everyMs: number | null; clock: Clock })`
    - methods `start(): void`, `stop(): void`, `refresh(): Promise<void>`,
      `state(): SourceState<T>`, `onChange(cb: () => void): () => void`

- [ ] **Step 1: Write the failing tests.**
  - `keeps the last good data and its age when a read fails`: the first read returns `{n:1}`
    at t=0; the second throws `"boom"` at t=30000. Assert `data` is `{n:1}`, `at` is 0 and
    `error` is `"boom"`.
  - `reports unavailable with no data when the first read fails`: assert `data` is null
    and `error` is set.
  - `coalesces overlapping refreshes into one read`: calling `refresh()` twice while a read
    is pending calls `read` once.
  - `never runs two reads at once on its schedule`.
- [ ] **Step 2: Run the tests.** `just test-one tests/source.test.ts` → FAIL.
- [ ] **Step 3: Implement `Source`, `systemClock`, `fakeClock` and `bunExec`.**
  `bunExec` uses `Bun.spawn` with a timeout that kills the child; the default is 10000 ms.
- [ ] **Step 4: Run the tests.** `just test-one tests/source.test.ts` → PASS. Then
  `just test-fast`.
- [ ] **Step 5: Commit.** `feat: sources keep last good data with its age`.

### Task 4: The familiar source: sessions, states, expiry

**Files:**
- Create: `src/familiar.ts`
- Test: `tests/familiar.test.ts`, `tests/fixtures/familiar/`
  (`agents.json`, `intent.json`, `niri-windows.json` trimmed from real records, with
  invented session ids)

**Interfaces:**
- Consumes: `Clock`, `Source` (Task 3)
- Produces:
  - `type HarnessState = "needs-input" | "needs-approval" | "error" | "working" | "done" | "idle"`
  - `URGENCY: readonly HarnessState[] = ["needs-input", "needs-approval", "error", "working", "done", "idle"]`
  - `interface Session { sessionId: string; project: string; repoRoot: string; color: string; member: string; state: HarnessState; sprite: string | null; updatedAt: number; pid: number; harness: string; workspaceId: number | null }`
  - `readFamiliar(dir: string, now: number, procAlive: (pid: number) => string | null): { sessions: Session[]; nextExpiryMs: number | null }`.
    `procAlive` returns the process name from `/proc/<pid>/comm`, or null when the process
    is gone.
  - `familiarSource(dir: string, clock: Clock): Source<{ sessions: Session[] }>`, which
    watches `dir` (debounced 100 ms) and arms a timer at `nextExpiryMs`.

- [ ] **Step 1: Write the failing tests.**
  - `uses after once expiresAt has passed`: an intent with `current.state = "done"` and
    `expiresAt = 1000`, read at now=999 gives `done`; at 1001 it gives `after`'s state
    (`idle`).
  - `drops a session whose pid is gone`: `procAlive` returns null, so the session is
    absent.
  - `takes harness from the process name`: `claude` gives `claude-code`, and `codex` gives
    `codex`; anything else is shown verbatim.
  - `returns the earliest future expiresAt as nextExpiryMs`.
  - `recomputes once per burst of renames`: three rename events within 50 ms cause one
    read.
  - `reports unavailable when the directory is missing`.
- [ ] **Step 2: Run the tests.** `just test-one tests/familiar.test.ts` → FAIL.
- [ ] **Step 3: Implement.**
  - Session ids come from `agents.json`.
  - State and sprite come from `intent.json`'s `current`, or its `after` once `expiresAt`
    has passed.
  - Colour comes from the intent's `color.project`.
  - `workspaceId` comes from `niri-windows.json`.
  - A file that fails to parse mid-rename keeps the previous good state, and the next
    event retries.
- [ ] **Step 4: Run the tests.** `just test-one tests/familiar.test.ts` → PASS. Then
  `just test-fast`.
- [ ] **Step 5: Commit.** `feat: familiar sessions with expiry and liveness`.

**Interfaces:**

  - `interface ProjectRow { prefix: string; name: string; root: string; color: string | null; todo: number; doing: { claimed: number; unverified: number; parked: number; unattended: number }; blocked: number; owed: number; quiet: number; scope: number; halted: boolean; lastActivity: string }`
  - `readTasks(exec: Exec, isPersonal: (root: string) => Promise<boolean>, now: number, recentDays = 7): Promise<{ rows: ProjectRow[]; claims: Claim[]; titles: Map<string, string> }>`
  - `profileFilter(exec: Exec): (root: string) => Promise<boolean>`: runs
    `ops-profile resolve <root> --json` and caches the result per root for the process
    lifetime.
  - `tasksSource(exec: Exec, clock: Clock): Source<…>`, with `everyMs = 30000`.

- [ ] **Step 1: Write the failing tests.** Fixtures cover:
  - `tasks projects`
  - `tasks list --all-projects --status todo --status doing --status blocked`
  - `tasks claims`
  - `tasks list --parked --all-projects`
  - `tasks list --needs-review --all-projects`
  - `tasks -C <wt> show <id> --no-fetch`

  Tests:
  - `prefers the worktree copy a claim names`: main says doing, the worktree says blocked
    and parked. It counts as blocked, and its owed park still counts.
  - `falls back to the registered record when the named worktree is gone`: `-C` exits
    non-zero, so the main record counts.
  - `splits only doing members, and the parts sum to doing`: a doing task that is both
    claimed and parked counts as claimed.
  - `keeps unverified claims visible`: `live: true, unverified: "pid view"` gives
    `claimed 1, unverified 1`.
  - `counts an owed park on a todo task`.
  - `keeps a quiet project that owes a review`: last activity 30 days ago, one park
    waiting on the user, so the row is present.
  - `drops work-profile projects`: `isPersonal` returns false, so there is no row.
  - `flags a project with an open halt-tagged task as halted`.
  - `re-reads worktree records on every refresh`: a task blocked between refreshes, with
    its park unchanged, moves from todo to blocked.
  - `orders rows owed first, then halted, then by last activity`.
- [ ] **Step 2: Run the tests.** `just test-one tests/tasks.test.ts` → FAIL.
- [ ] **Step 3: Implement `readTasks` as the spec's population rule.**
  The members are the open list plus the claimed and parked ids. For every live claim or
  park that names a worktree, read that copy with `tasks -C <wt> show <id> --no-fetch`;
  otherwise use the registered record. Count every status from that record, and partition
  only doing. Run the worktree reads with at most 4 concurrent. Titles come from the same
  records. `halted` means the project has an open member tagged `halt`. `quiet` counts
  owed parks whose reason is `quiet`. `scope` counts the project's `--needs-review`
  rows.
- [ ] **Step 4: Run the tests.** `just test-one tests/tasks.test.ts` → PASS. Then
  `just test-fast`.
