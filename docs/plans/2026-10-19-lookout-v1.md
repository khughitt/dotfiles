# lookout v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a read-only terminal overview of live agents, task state and obs failure signals,
shown in a niri kitty quick-access dropdown, that is instant to open and never shows a
guessed number.

**Architecture:** independent data sources, each on its own refresh schedule, publish
`SourceState<T>` (last good data, age, unavailable reason) into pure model functions. The
model functions build an immutable `View`, and an OpenTUI (Solid) layer renders it. Every
source reads only a tool's own command or published file, through an injectable `Exec`
and an injectable clock, so the tests run on fixtures.

**Tech Stack:** TypeScript, Bun 1.4, `@opentui/core` and `@opentui/solid` 0.5.11 (as
mindful-tui pins), `solid-js` ^1.9, `bun test`, Biome. kitty graphics protocol for the
portraits.

**Spec:** `docs/specs/2026-10-18-ops-dashboard-design.md`. It lives in dotfiles until
Task 1 copies it into lookout.

## Global Constraints

- Read-only. No `tasks` write, no lock taken, no `tasks/*.md` parsed, no attempt
  directory or thought or inbox body read.
- Never read the obs index from a refresh loop, and never run `obs index`,
  `dashboard build` or `ANALYZE`. Read only
  `$XDG_STATE_HOME/obs/dashboard/snapshot.js`.
- Refresh schedules:
  - agents: on changes to familiar's directory, plus a claims read every 2 s, plus a timer
    at each intent `expiresAt`
  - tasks: every 30 s
  - obs: on changes to the snapshot file
- A failing source keeps its last good data with its age, or shows
  `unavailable (<reason>)`. It never shows a guessed zero.
- `personal` projects only. One shared allowlist (Task 3's `PersonalProjects`, built
  from `ops-profile resolve <root> --json`) filters every module before anything is
  rendered or totalled: task rows, familiar cards, and obs rates and hotspots. One host per
  view, named in the header.
- Workspace: Task 1 makes lookout's first commit on its `main`. Tasks 2–8 then run in one
  lookout worktree, `.worktrees/v1`: run `work-link --ensure .worktrees` before
  `git worktree add`, lock the worktree, then `just setup`. The branch merges when Task 8
  closes. Task 9 runs in a dotfiles worktree.
- Doing splits into claimed (with unverified kept visible), parked and unattended, over
  the one reconciled population (spec, Constraints).
- Task 1 creates the project as `lookout`: tasks prefix `look`, checkout `~/d/lookout`,
  `personal` profile, GitHub `khughitt/lookout`.
- Gated actions, which the owner approves in the moment:
  - creating the GitHub repository and pushing to it
  - `just projects` in ops plus `just assemble` in lore (a live global-instructions change)
  - any use of the live desktop (the spike, the live checks)

## Review Focus

1. **A source that is down at start-up** (no snapshot on europa, no familiar directory):
   that module reads `unavailable (<reason>)` and the others render normally. Pinned in
   Task 3 and Task 8.
2. **A worktree that a claim or park names has been removed:** the task falls back to its
   registered record and the dashboard does not throw. Pinned in Task 5.
3. **Clock and day boundaries:** obs days are cut in the snapshot's own `tz`
   (America/Los_Angeles) while the host runs US/Eastern. "Yesterday" is obs's yesterday.
   Pinned in Task 6.
4. **A session whose pid is gone but whose familiar record is still current:** it is not
   counted as live. A claim reported `live: true` with `unverified` shows as unverified.
   Pinned in Task 4 and Task 5.
5. **A burst of familiar file renames** (atomic replace: several events per write):
   one recompute per burst, with no partial reads. Pinned in Task 4.

### Task 4: The familiar source: sessions, states, expiry

**Files:**
- Create: `src/familiar.ts`
- Test: `tests/familiar.test.ts`, `tests/fixtures/familiar/`
  (`agents.json`, `intent.json`, `niri-windows.json` trimmed from real records, with

**Interfaces:**
- Consumes: `Clock`, `Source`, `PersonalProjects` (Task 3)
- Produces:
  - `type HarnessState = "needs-input" | "needs-approval" | "error" | "working" | "done" | "idle"`
  - `URGENCY: readonly HarnessState[] = ["needs-input", "needs-approval", "error", "working", "done", "idle"]`
  - `interface Session { sessionId: string; project: string; repoRoot: string; color: string; member: string; state: HarnessState; sprite: string | null; updatedAt: number; pid: number; harness: string; workspaceId: number | null }`
  - `readFamiliar(dir: string, now: number, proc: (pid: number, starttime: number) => string | null, allow: PersonalProjects): { sessions: Session[]; nextExpiryMs: number | null }`.
    `proc` returns the process name from `/proc/<pid>/comm` only when field 22 of
    `/proc/<pid>/stat` equals the `starttime` familiar recorded, and null otherwise (gone
    or recycled). Sessions whose canonical (realpath) `repoRoot` is not in `allow.roots` are
    dropped.
  - `familiarSource(dir: string, clock: Clock, allow: PersonalProjects): Source<{ sessions: Session[] }>`.
    It watches `dir` (debounced 100 ms) and arms a timer at `nextExpiryMs`. When `dir` is
    absent it watches the nearest existing parent and reattaches once `dir` appears, with a
    60 s retry as a backstop.

  - `reports unavailable when the directory is missing`.

### Task 6: The obs source: rates and hotspots from the snapshot

**Files:**
- Create: `src/obs.ts`
- Test: `tests/obs.test.ts`, `tests/fixtures/obs/snapshot.js` (a small hand-built
  snapshot in the real shape: `window.OBS_SNAPSHOT = {schema:1, host, built_at_ms, tz, window, measures:[{harness, measure, available}], tables:{tools:{columns,rows}, failed_calls:{columns,rows}}}`)

**Interfaces:**
- Consumes: `Clock`, `Source`, `PersonalProjects` (Task 3)
- Produces:
  - `type Rate = { status: "rate"; calls: number; errors: number } | { status: "not-recorded" } | { status: "no-calls" }`
  - `interface ObsView { host: string; builtAt: number; tz: string; yesterday: Rate; week: Rate; partial: boolean; hotspots: { project: string; tool: string; failures: number }[]; hotspotsPartial: boolean }`
  - `readObs(text: string, allow: PersonalProjects): ObsView`. It parses the JSON between
    the first `{` and the last `}` and reads columns by name, never by position. It keeps
    only rows whose `project` is in `allow.prefixes`; rows with a null project are dropped. Rows whose `errors` is null are not recorded:
    they are excluded from both numerator and denominator, and set `partial`. A harness
    whose `measures` entry for `tool_calls` or `tool_errors` reads `available: false`
    contributes no rows to the rate and sets `partial`. Hotspots read `failed_calls` only
    from harnesses whose `failed_calls` measure is available, and carry their own
    `hotspotsPartial`.
  - `obsSource(path: string, clock: Clock, allow: PersonalProjects): Source<ObsView>`. It
    watches the parent directory, because the snapshot is replaced by atomic rename, and
    re-reads when the snapshot's name changes. It reattaches if the directory itself
    appears later.
